# 植物识别本地训练系统实现方案

日期：2026-03-21  
项目代号：`plant-local`

## 1. 建设目标
建设一套本地可部署的植物识别平台，支持完整流程：
`数据导入 -> 标注/复核 -> 训练 -> 批量识别 -> 结果导出 -> 模型版本管理`

目标定位：我方负责平台开发交付，客户负责后续数据维护与模型持续训练。

## 2. 范围定义
### 2.1 本期范围
- 图片批量导入（文件夹/压缩包）
- 图像级二分类标注（目标植物/非目标植物）
- 一键训练、继续训练
- 单图和批量识别（返回类别 + 置信度）
- 结果导出（CSV/JSON）
- 模型版本管理（发布、切换、回滚）

### 2.2 非本期范围
- 固定识别准确率承诺
- 长期数据标注服务
- 高可用集群与容灾架构
- 7x24 运维驻场

## 3. 总体技术架构
### 3.1 技术选型
- 前端：React + Ant Design
- 后端：FastAPI
- 训练框架：PyTorch
- 推理引擎：ONNX Runtime（可选直连 PyTorch）
- 数据库：SQLite（后续可切 PostgreSQL）
- 任务执行：本地任务队列（单机）

### 3.2 架构分层
1. Web 层：上传、标注、训练发起、结果查看  
2. API 层：数据管理、训练任务、推理任务、模型管理  
3. 算法层：数据预处理、训练、评估、导出  
4. 存储层：业务库 + 文件存储（图片、模型、日志）

## 4. 功能设计
### 4.1 数据管理模块
- 导入图片并记录元信息（名称、路径、哈希、状态）
- 基础校验：文件格式、损坏图片、重复图片
- 数据集划分：train/val（默认 8:2）

### 4.2 标注与复核模块
- 标注值：`target_plant`、`other`
- 提供“待复核”列表，支持人工纠错
- 纠错样本自动进入“待训练池”

### 4.3 训练模块
- 训练模式：
  - 新模型训练
  - 继续训练（基于历史模型）
- 输出内容：
  - 模型文件
  - 指标（acc/precision/recall/f1）
  - 训练日志

### 4.4 识别模块
- 单图识别 API
- 批量识别任务（支持 1 万张）
- 结果字段：文件名、预测类别、置信度、处理状态、错误信息

### 4.5 模型管理模块
- 版本列表（版本号、创建时间、指标、备注）
- 一键发布当前版本
- 回滚到历史版本

## 5. 数据与目录规范
建议目录结构：

```text
plant-local/
  data/
    raw/
    labeled/
    split/train/
    split/val/
  models/
    v1/
    v2/
  outputs/
    predictions/
    reports/
  logs/
```

核心表（最简）：
- `images`：图片主数据
- `labels`：标注记录
- `train_jobs`：训练任务
- `infer_jobs`：识别任务
- `model_versions`：模型版本

## 6. 关键接口（V1）
- `POST /api/data/import`：导入图片
- `POST /api/label/save`：提交标注
- `POST /api/train/start`：启动训练
- `GET /api/train/{job_id}`：训练状态
- `POST /api/infer/start`：启动批量识别
- `GET /api/infer/{job_id}`：识别状态
- `GET /api/infer/{job_id}/export`：导出结果
- `POST /api/model/publish`：发布模型
- `POST /api/model/rollback`：回滚模型

## 7. 实施计划（4-6 周）
### 第 1 周
- 需求冻结与原型确认
- 项目骨架搭建（前后端 + 训练脚本）
- 数据目录与数据库初始化

### 第 2-3 周
- 完成数据导入、标注、训练、识别主链路
- 完成导出能力与基础日志

### 第 4 周
- 完成模型版本管理
- 联调、修复、初版文档

### 第 5-6 周（可选优化）
- 稳定性增强（失败重试、异常处理）
- 易用性优化与交付培训

## 8. 验收标准
- 端到端流程可跑通：导入 -> 标注 -> 训练 -> 识别 -> 导出
- 可完成 1 万张图片批量识别并导出
- 模型版本可发布、切换、回滚
- 无阻断级缺陷（P1）

## 9. 风险与应对
- 数据质量波动：建立标注规范与抽检机制
- 客户环境差异：提供 GPU/CPU 两套部署手册
- 模型效果波动：采用固定验证集与版本回滚机制

## 10. 交付清单
- 可部署系统（前端 + 后端 + 训练任务）
- 训练与推理脚本
- 部署手册、操作手册
- 验收记录与问题闭环清单
